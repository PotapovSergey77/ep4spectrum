# Что кладётся в корень SD-карты

Содержимое этого каталога копируется на карту как есть, поверх обычной
установки ESXDOS.

```
/128.rom          32768   Spectrum 128K:  ROM 0 + ROM 1
/pentagon.rom     32768   Pentagon 128:   ROM 0 + 48 BASIC
/trdos.rom        16384   TR-DOS
/bin/romload        900   dot-команда загрузки
```

Образы собраны из файлов в `rom/` и сверены с ними по началу каждого
банка. `pentagon.rom` — банки 2 и 3 из `rom/pentagon.rom`, где банк 2
это ROM 0 (узнаётся по задержке `f3 01 2b 69`), а банк 3 — 48 BASIC
(`f3 af 11 ff ff c3 cb 11`). `trdos.rom` — банк 1, он узнаётся по
`OUT (FE),A` в первых байтах: TR-DOS ставит бордюр на входе.

Порядок внутри 32К задаёт `page_rom_sel`, бит 4 порта `0x7FFD`: по нулю
читается первая половина, по единице вторая. После сброса бит нулевой,
поэтому машина стартует в меню 128.

## Как это работает

ESXDOS уже умеет FAT, поэтому файловая система осталась в софте, а ПЛИС
даёт только вход:

| порт | направление | назначение |
|---|---|---|
| `0x9B` | запись | `[1:0]` слот, `[2]` сброс счётчика, `[3]` пометить заполненным, `[4]` снять |
| `0x9B` | чтение | `[3:0]` флаги заполненности |
| `0x9F` | запись | байт, счётчик шагает сам |

Область `0x0000–0x3FFF` недоступна для записи из памяти всегда, без
разрешающего бита: адрес, куда ляжет байт, берётся из счётчика слота
внутри ПЛИС, а не с шины. Программа не может ни перезаписать ПЗУ, из-под
которого работает, ни направить запись в чужой слот.

Машина читает ПЗУ из SDRAM только если её слот помечен заполненным.
Не помечен — работает прежний образ 48K из блочной памяти. Поэтому
карта без этих файлов загружается ровно как раньше и может напечатать
сообщение о том, чего не хватает.

Слоты разведены с DivMMC по старшему биту адреса: у DivMMC
`rom_addr[19]` единичный, у всех слотов нулевой. Пересечься они не могут
конструктивно, а не по расчёту адресов.

## Запуск

Пока — вручную, командой `.romload`, и это правильный порядок: сначала
убедиться, что загрузка работает, потом автоматизировать.

Автозапуск делается через `autoexec.bas` в корне карты. **Механизм не
проверен** на той сборке ESXDOS, что стоит здесь, — у разных версий он
отличается, и гадать смысла нет. Как только `.romload` отработает
вручную, автозапуск дописывается одной строкой.

## Проверка без ассемблера

Канал можно проверить прямо из BASIC, до всякой команды:

```basic
OUT 155,4 : REM слот 0, сброс счётчика
OUT 159,1 : OUT 159,2 : REM два байта
OUT 155,8 : REM пометить заполненным
PRINT IN 155 : REM должно вернуть 1
```

Это подтверждает, что порты декодируются и арбитраж SDRAM пропускает
запись, независимо от того, собрана команда или нет.
